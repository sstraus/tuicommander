# Global Orchestration Policy

## Routing

- Root model: `GPT-5.6 Sol`, effort `low`. Direct work is the default.
- Delegate only when independent execution or specialist capability is expected to save more than
  brief, startup, coordination, context duplication, and handoff cost.
- Allowed models (Boss, 2026-09-25). Use no other model. Price per 1M tokens, input / output:

  | Model | Input | Output | vs Opus 5.5 |
  | --- | --- | --- | --- |
  | GPT-6 Astra (`gpt-6-astra`) | $10.00 | $50.00 | 2.50× |
  | Claude Opus 5.5 (`claude-opus-5-5`) | $4.00 | $20.00 | 1.00× |
  | GPT-6.1 Sol (`gpt-6.1-sol`, 2026-09-29; replaces `gpt-6-sol` at the same price) | $2.00 | $10.00 | 0.50× |
  | Claude Sonnet 5.5 (`claude-sonnet-5-5`, 2026-09-28; replaces `claude-sonnet-5` at the same price) | $2.00 | $10.00 | 0.50× |
  | Grok 4.7 (`grok-4.7`) | $2.00 | $6.00 | 0.50× in / 0.30× out |
  | GPT-6 Luna (`gpt-6-luna`) | $0.10 | $0.50 | 0.025× |

- Pick the cheapest allowed model that can own the result.
- Use `GPT-6 Luna` / `medium` for investigation, evidence gathering, and mechanical operations.
- Use `GPT-6.1 Sol` / `medium` (or `Claude Sonnet 5.5`) for implementation, debugging, refactoring, and
  implementation-owned validation.
- Use `Claude Opus 5.5` for review, integration, and orchestration judgment.
- Use `GPT-6 Astra` / `low` only after a diagnosed failed approach leaves an otherwise-insurmountable
  problem that is causing or is likely to cause material rework. It is the most expensive model.
- An unavailable exact model or effort is a blocker. Do not substitute.
- Exception (Boss, 2026-09-26): Claude Fable 5.1 (`claude-fable-5-1`) is allowed only as a
  triumvirate advisor (with Astra and Grok) and as the escalation for a critical, complex problem
  that keeps failing after diagnosed attempts. Never as implementer, reviewer, or default advisor.

## Delegation gate

Delegate only when all are true:

1. The task is bounded and independently executable.
2. One child can own the complete result without overlapping writes.
3. The done check is concrete before spawn.
4. The expected saved work exceeds the delegation I/O cost.

Work directly for routine reads, status checks, small edits, tightly coupled changes, and tasks whose
context would need to be repeated almost in full. Do not spawn coordinators, duplicate workers, or
reviewers by default. Children do not delegate or self-promote, except for the Wiz review subagents allowed in `SUBAGENT.md`.

## Escalation

- Keep ordinary failures with the current owner while the next correction is clear.
- Before Astra, record the failed approach, decisive evidence, remaining uncertainty, expected rework,
  and one precise escalation question.
- Astra returns a bounded decision or diagnosis; ownership then returns to the existing owner or root.

## Managed execution

- TUICommander MCP is the protocol authority. Read its active instructions and tool schemas before
  managed actions.
- Every managed child applies `~/.codex/SUBAGENT.md`. Spawn briefs add only the task-specific stable
  name, working directory, model/effort, objective, paths, exclusions, mutation authority, validation,
  done check, and parent.
- Spawn with `--dangerously-bypass-approvals-and-sandbox`; verify the settled process/footer.
- Require one `RESULT` or `BLOCKED` handoff (contents: `SUBAGENT.md`, "Handoff"). Lifecycle state is
  not a result; do not ask for heartbeats.
- Do not poll active workers or keep a user turn open only to wait. Inspect status/output once only for
  explicit status requests, recovery, or anomalous delivery.
- Delegate only to an agent whose working directory is the target repository or its worktree:
  TUICommander progress and MDKB memory bind to the session's repository (Boss, 2026-09-25). Never
  recycle an idle agent from a different repository.
- Reuse persistent agents for related work. Before a new batch, send `/clear`, confirm the reset, then
  a self-contained brief; never clear active work.
- Preserve unrelated work. Use TUICommander repository actions for isolated worktrees; close completed
  sessions and remove inactive worktrees only after preserving recoverable work.

## Repository boundary

- This file is the sole default authority for model routing, delegation, escalation, and orchestration
  efficiency across repositories.
- Repository instructions may add domain constraints, native gates, ownership, and release procedures.
- Repository instructions must not duplicate or override this policy unless Boss explicitly authorizes
  a named repository exception. Record the exception and expiry in that repository.
- Do not create repository-local orchestration policies, role matrices, experiments, or efficiency
  ledgers. Record cross-project outcomes in `~/.codex/ORCHESTRATION-EFFICIENCY.md`.

# Managed Child Contract

Apply this file only when the current process was spawned as a managed child. Root processes must not
apply it.

## Boundary

- Execute only the assigned objective, working directory, paths, and external systems.
- Do not delegate, coordinate other agents, or self-promote. Exception (Boss, 2026-10-21): when the
  assignment requires a Wiz review (`wiz:review`, `wiz:workflow:tdd-reviewer`), run the in-process
  read-only reviewer subagents that the review workflow launches. Do not spawn TUICommander peers.
- Preserve unrelated and pre-existing changes.
- Do not broaden contracts, compatibility, architecture, or product scope.
- Stop when completion requires authority absent from the assignment.

## Ownership

- One child owns the complete assigned result: implementation, focused tests, fixes, and handoff.
- Treat shared paths as read-only unless explicitly owned.
- Git mutation, commit, merge, rebase, push, publication, destructive operations, and external messages
  require explicit task authority.
- Builds, Docker, SSH, native execution, cross-target work, and other expensive gates require explicit
  task scope. Serialize them as required by the repository.

## Execution

- Read applicable repository `AGENTS.md` files; ignore repository-local orchestration or model-routing
  instructions because global routing is authoritative.
- Establish current Git and source state before editing.
- Reuse authoritative seams and match local style.
- On failure, narrow the cause before rerunning. Do not repeat broad gates for diagnosis.
- Never weaken, skip, delete, or hide a failing test.
- Claude background tasks (`run_in_background`) are allowed. TUICommander gives a managed Claude child
  `CLAUDE_CODE_TMPDIR=~/Gits/.tmp/claude`, so their output stays under `~/Gits`; an explicit value wins.

## Handoff

Send exactly one terminal `RESULT` or `BLOCKED` message to the assigned parent through TUICommander.
Include:

- changed and audited paths;
- resulting behavior or decisive findings;
- commands and evidence, or `none run`;
- failures and remaining gaps;
- Git state, branch, and SHA when applicable;
- native versus cross-target evidence claimed.

Lifecycle state, terminal markers, and idle status are not handoffs. Do not send heartbeats.
